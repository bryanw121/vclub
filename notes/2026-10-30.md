Database hardening landed (locked-down database functions, a fix for the broken kudos reminder job), and every PR now gets an accessibility check.

## Shipped

**Fixes / under the hood**
- Database hardening: the 12 privileged ("security definer") functions now use a fixed search path, guests can no longer call signed-in chat and notification functions, and trigger/cron-only functions can't be called by any client. Also fixes the "kudos reminders" job, which used a notification type the database rejects and would have failed the first time an event ended with attendees; it now sends "Time to give cheers!" reminders and respects each player's Cheers reminders switch. No app code changed (#111)

```mermaid
sequenceDiagram
  participant Cron as pg_cron (kudos-reminders)
  participant Fn as send_kudos_reminders() (definer, search_path public)
  participant DB as Postgres
  participant App as App (inbox / bell)
  Cron->>Fn: run
  Fn->>DB: events that ended in the last 15 min, not cancelled,<br/>no cheers_reminder yet for that event
  Fn->>DB: attending players where notification_pref_enabled(user, in_app, cheers_reminder)
  Fn->>DB: insert notifications (cheers_reminder, deep_link /event/id?tab=3)
  DB-->>App: shows in inbox; tap opens the event's Cheers tab
```

| Object | Change | Notes |
