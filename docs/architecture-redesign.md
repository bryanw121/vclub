# Architecture redesign (October 2026)

Status: in progress. This document is the plan; CLAUDE.md is the rulebook and is
updated as each phase lands.

## Verdict

Three audits (UI structure, data layer, backend/CI) agreed on the same picture:
the product logic is sound, but it is held together by per-screen improvisation.
A rewrite is not justified; an incremental redesign is, because the same five
root causes account for almost every finding:

1. **No data layer.** 93 direct `supabase.from()` calls in screens, four hand-rolled
   caches with different TTLs that live in refs and die on unmount, invalidation
   that amounts to "refetch everything on focus", and errors that surface as empty
   states or endless spinners instead of messages. Realtime channels share topic
   names across components, so one component unmounting silently kills another's
   subscription (chat going stale is this bug).
2. **Navigation defined six times.** Tabs, create-menu options, breakpoints and
   route strings are copied between the sidebar layout, the mobile tab layout, the
   pager, the doc-scroll hook and 57 `router.push(... as any)` calls. They have
   already drifted (web FAB only on Events; badge colours differ).
3. **Four screens of 1,000–2,500 lines** (event, tournament, profile, host) each hold
   fetching, forms, modals, drag-and-drop and dead code (an unreachable discussion
   drawer, an unused month pager, a second copy of the avatar-border renderers).
4. **Design tokens bypassed.** 1,371 inline style objects vs 436 `shared.*` uses;
   163 hex literals in TSX (91 are `#fff`); 7 chip variants, 12 icon-button
   size/radius combos, 9 hand-built back headers, 28 hand-rolled modals.
5. **The DB contract is hand-written and unverifiable.** No generated types,
   25 tables with no migration, select strings built by concatenation, and two
   security gaps: the push edge function accepts unauthenticated POSTs, and the
   e2e account password is committed to the public repo.

## Target shape

```
lib/
  env.ts          validated EXPO_PUBLIC_* (one place that reads process.env)
  query.ts        module-level cache + useQuery/useMutation (no third-party lib)
  realtime.ts     ref-counted channel registry with status + AppState resubscribe
  supabase.ts     createClient<Database>, AppState-aware token refresh
constants/
  navigation.ts   TABS, CREATE_MENU — the only definition of the tab bar
  layout.ts       BREAKPOINTS
  cache.ts        STALE windows
  selects.ts      PostgREST select fragments (PROFILE_BRIEF, COMMENT, GUEST…)
utils/routes.ts   routes.event(id) etc. — the one `as any`
hooks/            one hook per concern, built on lib/query: useMyProfile,
                  useEventFeed, useEvent, useClub, useConversations, useMessages…
components/ui/    ScreenState, ScreenHeader, Chip, IconButton, EmptyState,
                  ConfirmDialog, BottomSheet, Avatar; Button/Input grow props
app/              screens compose hooks + components; no direct supabase calls
                  for reads, no inline modals, no hex literals
supabase/
  config.toml     verify_jwt per function (committed, not dashboard-only)
  functions/_shared/  client + Expo helpers + webhook auth
types/database.ts generated by `supabase gen types`; types/index.ts derives from it
```

### Data layer contract (`lib/query.ts`)

- `useQuery(key, fetcher, { staleMs, enabled })` returns
  `{ data, error, isLoading, isFetching, refetch }`. `isLoading` is true only
  when there is no data yet; a failed refetch keeps the last good `data` and
  sets `error`.
- Cache is module-level and keyed by string (`['event', id]` joined), so it
  survives unmount and tab switches on wide web. In-flight fetches are deduped.
- `invalidate(prefix)` marks keys stale and refetches the ones with mounted
  readers. `setQueryData(key, updater)` supports optimistic updates.
- `useMutation(fn, { onMutate, onError, invalidates })` guards double submit and
  rolls back `onMutate` changes on error.
- Focus/AppState refetch only when stale; `STALE` windows come from
  `constants/cache.ts`.
- `lib/dataVersion.ts` was a thin shim over `invalidate` during migration; removed in Phase C once it had no callers.

Why hand-rolled: CLAUDE.md forbids third-party state management. The API
mirrors TanStack Query on purpose so a later swap is mechanical.

### Realtime contract (`lib/realtime.ts`)

- `useRealtimeChannel(topic, bindings, { enabled })`: ref-counted per topic; the
  channel is created on first subscriber and removed on last. Bindings are
  attached before `subscribe()`.
- Status callback: on `CHANNEL_ERROR`/`TIMED_OUT` or AppState → `active`, the
  registry resubscribes and callers get an `onReconnect` to refetch.
- Message/reaction handlers build rows from the payload; they do not refetch
  page 1.

## Phases

Each phase is one PR, reviewed by an independent agent, with typecheck, unit
tests, web export + guest/signed-in renders, and CI green before merge.

**Phase A — foundations (parallel, disjoint files).**
A1 `lib/query.ts`, `lib/realtime.ts`, tests. A2 navigation/layout/cache
constants, `routes.ts`, both layouts derive from them. A3 backend hardening:
`config.toml`, webhook secret, shared edge code, pinned imports, e2e creds from
secrets, CI timeouts + readiness wait. A4 UI primitives + theme tokens.

**Phase B — adopt (parallel by screen area).**
B1 feed on `lib/query` (cache survives unmount; join-from-card fixed; error
keeps data). B2 chat on `lib/realtime` (per-instance topics, reconnect,
payload-driven updates, failed-send retry, shared conversations store).
B3 event detail decomposed into hooks + components, dead drawer removed.
B4 profile/club/host: `useMyProfile`, spinner fix, duplicate avatar borders
removed, select fragments, no `select('*')`. B5 tournament: schedule generator
to `lib/`, write error checks, transactional RPCs.

**Phase C — consistency sweep.** Generated DB types wired into the client;
hex/gradient/medal tokens codemod; route helper adoption; docs fingerprint
narrowed to extracted facts; CLAUDE.md rewritten to match.

## Non-goals

- No visual redesign; screens should look the same after each phase.
- No Expo SDK upgrade in these PRs (separate branch).
- No change to the Reclub scraping approach.
